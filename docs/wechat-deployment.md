# 通识卡微信小程序上线操作手册

核对日期：2026-11-07。本文是操作说明，不是已部署证明。当前内容仍待人工审校；真实账号配置、付费资源开通及发布由负责人操作。平台菜单可能调整，以实际账号入口为准。

## 网站与工具

| 入口 | 地址 | 用途 |
| --- | --- | --- |
| 微信公众平台 | https://mp.weixin.qq.com/ | 注册、AppID、成员、订阅模板、备案、隐私、审核发布 |
| 微信开发者工具 | https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html | 导入项目、部署云函数、预览和上传 |
| 微信云开发 | https://cloud.weixin.qq.com/cloudbase | 云开发产品入口 |
| 腾讯云 CloudBase 控制台 | https://console.cloud.tencent.com/tcb | 管理已关联环境、数据库、函数及费用 |
| Node.js | https://nodejs.org/ | 安装 Node.js 22 与 npm |

推荐主路径：微信开发者工具顶部「云开发」进入该小程序关联环境。腾讯云控制台必须使用关联的账号，不能随便在另一个账号中新建环境。

本项目不需要购买独立服务器、配置 Nginx 或自建登录接口。云函数源码已在 `cloudfunctions/reminders/`，部署名称固定为 `reminders`；不要另外创建同名空白模板覆盖源码。

## 第一步：注册小程序、拿到 AppID

1. 打开 https://mp.weixin.qq.com/ ，没有账号则点击注册，选择「小程序」，不是公众号。
2. 按平台要求完成主体资料、管理员绑定、名称、头像、介绍和服务类目。选择符合实际业务的类目，不为获取订阅资格填写不实类目。
3. 根据后台提示完成认证、备案及对应资质。是否需要付费或额外材料以实际主体和平台要求为准。
4. 在「开发管理 → 开发设置」查找小程序 AppID，复制以 `wx` 开头的值；入口名称变化时搜索「开发设置」。
5. 在「成员管理」添加开发者，确保登录开发者工具的微信具有开发权限；后续测试者加入体验成员。

**成功标志**：后台能看到真实小程序 AppID，开发者能用自己的微信登录工具。不要用游客模式或测试号替代生产账号。

## 第二步：准备本地工程

在项目根目录打开终端，后面的命令除特别说明外都在这里运行：

```bash
node --version
npm --version
npm ci
```

Node.js 使用 22.x，npm 使用 9–11。Windows 可使用 PowerShell；在 WSL 开发时使用 WSL 终端，避免混用两套依赖安装目录。

打开 `src/manifest.json`，只把 `mp-weixin` 对象中的 `appid` 填成第一步取得的真实 AppID。顶部另一个 `appid` 是 uni-app 字段，不是本步骤要填的位置。保留其余配置及合法 JSON 格式。

先生成一次开发产物以导入工具；此时尚未填写云环境，页面提示未配置属于预期：

```bash
npm run dev:mp-weixin
```

保留这个终端运行。另开一个项目根目录终端：

```bash
npm run wechat:project -- dev
```

此命令生成根目录 `project.config.json`，指向 `dist/dev/mp-weixin/` 和 `cloudfunctions/`。如果提示缺少 AppID 或产物，先修正，不要伪造值绕过校验。

## 第三步：导入微信开发者工具

1. 从上表官网下载并安装稳定版微信开发者工具，用具有权限的微信扫码登录。
2. 选择「导入项目」，目录选择**仓库根目录**，不要只选择 `dist/dev/mp-weixin`。
3. 核对 AppID 与公众平台一致，项目类型为小程序，导入已有项目；不要创建新的模板覆盖工程。
4. 在编辑器确认能看到 `cloudfunctions/reminders`，以及生成的小程序页面。
5. 若项目在 WSL，Windows 文件选择器可尝试 `\\wsl.localhost\发行版名称\home\用户名\项目路径`；发行版名称以本机为准。若工具无法处理该路径，将工程放在工具能访问的 Windows 目录，在同一套环境重新安装和构建，避免只复制编译产物而漏掉云函数。

**成功标志**：工具识别真实 AppID，左侧存在 `cloudfunctions`，不再提示找不到小程序入口。

## 第四步：开通云开发、取得环境 ID

1. 在开发者工具顶部点击「云开发」，按引导开通当前小程序的云开发服务。
2. 阅读当前套餐、资源费用和试用限制；只有负责人确认费用后才创建或购买。不假设长期免费。
3. 创建环境，名称可按用途区分测试和生产；名称只是标签，**环境 ID 才是代码使用的值**。
4. 在环境总览／设置复制完整环境 ID，记下该环境关联的 AppID、用途和区域。
5. 推荐测试和生产分环境。后续集合、函数、模板配置、触发器都必须在所选环境重复配置；不要以为创建生产环境会自动复制测试数据。
6. 配置预算告警、资源用量和余额通知。没看到云开发入口时先检查工具版本、开发者权限及账号开通资格，不改用不关联的腾讯云账号绕过。

**成功标志**：进入环境后能看到数据库、云函数等管理入口，并复制到真实环境 ID。

## 第五步：创建三个数据库集合及权限

在「云开发 → 选择环境 → 数据库」操作，使用文档型数据库，不是 MySQL：

1. 点击「添加集合／新建集合」，分别创建 `card_progress`、`reminder_subscriptions`、`reminder_deliveries`，名称必须完全一致。
2. 分别打开每个集合的「权限设置／安全规则」，选择自定义规则，粘贴 `cloudfunctions/reminders/database.rules.json` 的完整内容并保存：

```json
{
  "read": false,
  "write": false
}
```

该规则禁止小程序客户端直接读写，不妨碍有权限的云函数访问。不要为了调试设置为所有用户可读写。

3. 在 `reminder_subscriptions` 的「索引管理」创建**非唯一联合索引**，字段按以下顺序添加：

| 顺序 | 字段 | 排序 |
| --- | --- | --- |
| 1 | `status` | 升序 |
| 2 | `nextSendAt` | 升序 |
| 3 | `_id` | 升序 |

4. 等待索引构建完成。其余集合使用内置文档 ID 索引，不需要为当前查询额外建索引。
5. 不用手工添加用户记录。首次打开由云函数创建进度；订阅授权并保存成功后才生成提醒记录。
6. 不对回执集合设置 TTL 或定期清空：回执用于防止重复保存和重复发送。停止提醒也不等于删除进度。

**成功标志**：三个集合存在、规则均已保存、联合索引可用。空集合是正常状态。

## 第六步：部署现有云函数

1. 在项目根目录安装云函数独立依赖，根目录的 `npm ci` 不会代替这一步：

```bash
npm --prefix cloudfunctions/reminders ci
```

2. 在开发者工具编辑器找到 `cloudfunctions`，通过右键菜单选择／切换到第四步的云环境，核对环境 ID。
3. 右键 `cloudfunctions/reminders`，选择「上传并部署」。可选「云端安装依赖」时由平台安装；本地依赖已按锁文件安装。不要仅上传 `index.js`。
4. 上传目录应包含 `index.js`、业务 JS、`cards.json`、`contract.json`、`config.json`、`package.json` 和锁文件等现有文件。不要替换成教程里的加法示例。
5. 在「云开发 → 云函数」确认函数名为 **`reminders`**，状态可用，部署时间为本次操作。
6. 打开该函数「配置／函数配置」，使用平台支持的 Node.js 18 或更新兼容运行时，执行入口为 `index.main`，超时时间设为 **60 秒**。若当前可选版本不同，需在该版本重新验证，不套用已停止支持的运行时。
7. 核对 `config.json` 声明的云调用权限 `subscribeMessage.send` 已生效；若控制台要求授权，按提示完成。

这里只部署了后端，**没有发布小程序，也没有启用定时器**。不要为此购买普通云服务器或自行部署 HTTP 登录服务。

**成功标志**：云端存在 `reminders`，依赖安装完成；日志中没有 `Cannot find module`、入口不存在或运行时不兼容错误。

## 第七步：申请真实订阅模板

1. 登录 https://mp.weixin.qq.com/ ，进入「功能 → 订阅消息」（也可能直接名为「订阅消息」）。
2. 从公共模板库选择符合真实业务和账号类目的模板，选取所需关键词，添加到「我的模板」。没有适合模板时按平台入口申请，不编造模板 ID。
3. 打开模板详情，记录**模板 ID、一次性／长期类型、每个关键词对应的字段键与填写规则**。字段键类似 `thing` 加数字，具体数字只能从你自己的模板详情获取。
4. 至少需要一个语义适合卡片标题的 `thingN` 字段，用来填写下一张卡片标题。其他必填字段也必须按模板语义填全。
5. 一次性和长期是两种平台能力，分别配置对应真实模板。普通账号未必有长期订阅资格；不能把一次性模板填到长期变量中，也不能把「总是保持以上选择」当作无限次授权。
6. 没有长期资格时，将下一步的 `REMINDER_LONG_ENABLED` 设为 `false`，仅开放一次提醒。若两种模板都没有，先将两种提醒都禁用，仍可测试云端领取；这不等于完整提醒功能已上线。

**成功标志**：后台真实存在可用模板，类型和字段已核对。不以测试用虚构 ID、复制他人模板 ID 或随意选择类目替代申请。

## 第八步：配置云函数环境变量

位置是「云开发 → 当前环境 → 云函数 → reminders → 配置 → 环境变量」或关联 CloudBase 控制台中的同一函数配置页。**不是前端 `.env.local`。**

| 变量名 | 填写内容 |
| --- | --- |
| `REMINDER_ONCE_ENABLED` | 有一次模板填 `true`，未开通填 `false` |
| `REMINDER_ONCE_TEMPLATE_ID` | 自己后台的一次订阅模板 ID |
| `REMINDER_ONCE_TEMPLATE_DATA` | 一次模板真实字段与文案的 JSON 对象 |
| `REMINDER_LONG_ENABLED` | 有长期资格且模板可用填 `true`，否则明确填 `false` |
| `REMINDER_LONG_TEMPLATE_ID` | 自己后台的长期订阅模板 ID |
| `REMINDER_LONG_TEMPLATE_DATA` | 长期模板真实字段与文案的 JSON 对象 |

启用标记只接受小写 `true`／`false`；不要填中文或 `0`／`1`。禁用模式可以不配置其 ID 和 DATA。两种模式默认启用，所以未开通时应显式禁用。

### DATA 怎样填写

不提供一份可直接照抄的字段编号，以免发送时字段与真实模板不匹配。按下面顺序制作每种模板的 JSON：

1. 从模板详情逐一复制真实字段键，作为 JSON 对象的属性名。
2. 每个字段的值必须是仅含 `value` 的对象，例如该字段的内容结构为 `{"value":"{{cardTitle}}"}`。外层属性名必须使用实际字段键。
3. 卡片标题对应的真实 `thingN` 字段，其 `value` 填 `{{cardTitle}}`。
4. 模板需要时间时，按该字段要求填 `{{scheduledAt}}` 或 `{{date}}`；其他必填字段填写真实、符合语义的固定文案。
5. 将整个 JSON 对象粘贴为环境变量值，不在对象外再套字符串引号；不包含注释、尾逗号或换行控制字符。
6. 一次与长期模板可能使用不同字段编号，分别制作，不能直接假设共用。

| 替换标记 | 运行时含义 |
| --- | --- |
| `{{cardTitle}}` | 发送时这个用户的下一张未领取卡片标题 |
| `{{scheduledAt}}` | 计划时隙，北京时间 `YYYY-MM-DD HH:mm` |
| `{{date}}` | 计划日期，北京时间 `YYYY-MM-DD` |

只支持这三个标记。标题必须出现在真实 `thingN` 字段；每个 thing 字段替换后的内容不得超过 20 个 UTF-16 单元。系统不会截断标题，超限会拒绝配置。其他字段的格式、长度和必填要求还需逐项按微信模板核对，不能只依赖本地校验。

保存配置后确认生效；如控制台提示重新部署／更新函数，完成该操作。不要把这些变量加上 `VITE_` 前缀，也不需要把 AppSecret、腾讯云 SecretId／SecretKey 放入仓库。

**成功标志**：小程序提醒设置能读取已配置模式；不是仅在控制台保存了六行文本就认定发送成功。

## 第九步：启用定时器

1. 确认当前环境和 `reminders` 函数正确。
2. 在开发者工具右键该函数，选择「上传触发器」。只上传代码不能代替此步骤。
3. 在函数触发器管理中核对名称 `reminder-dispatch`、类型 timer、表达式 `0 */5 * * * * *`，并确认启用。
4. 这是微信七字段 cron（秒、分、时、日、月、星期、年），时区 UTC+8，表示每五分钟检查一次；不要替换成 Linux 五字段格式。
5. 查看云函数日志，确认出现平台定时调用。没有到期用户时发送数量为零正常，不要为看到发送结果反复触发生产任务。

发送计划首次为保存后的次日北京时间 09:00，长期按 1／2／7 日间隔。五分钟轮询不是每五分钟给用户发一次，09:00 也不是保证精确送达。

**注意**：定时器启用后即使电脑关机也会运行，且可能产生费用。测试环境只能使用知情测试用户。不要在客户端或控制台手工传 `Type: Timer` 冒充平台触发器，本项目会校验可信来源；控制台手动调用没有用户 OPENID 时，领取接口被拒绝也不表示云函数损坏。

## 第十步：让前端连接正确云环境

1. 在项目根目录将 `.env.example` 复制为 `.env.local`，可直接用编辑器另存为。
2. 找到 `VITE_WECHAT_CLOUD_ENV=`，在等号后填写第四步复制的完整环境 ID，不是环境名称、AppID 或模板 ID。
3. 停止正在运行的开发编译，重新运行 `npm run dev:mp-weixin`；环境变量改变必须重编译。
4. 在开发者工具重新编译，打开首页。页面会真实调用云函数领取卡片。
5. 在同一云环境数据库查看 `card_progress`：应出现版本与领取日期／卡片 ID。文档 ID 由认证用户身份派生，不需要前端输入用户 ID。

只在浏览器运行 H5 不能测试微信身份、云端进度或微信授权；H5 是本机预览。旧本机历史不自动上传，云端第一次访问从第一张开始。测试和生产的进度也不会自动同步。

## 第十一步：真机验收，不要跳过

使用开发者工具「预览」二维码，在有权限的微信账号上打开；需要多人体验时，在后台上传版本并设为体验版、添加体验成员。先确认没有开启将请求重定向到本机的「云函数本地调试」。

| 场景 | 操作与预期 |
| --- | --- |
| 首次与同日重复打开 | 首次领一张，退出重进还是同一张；数据库同日只有一条领取记录 |
| 跨设备 | 同一个微信身份在另一设备进入，进度相同；不要用两个微信账号来测试同步 |
| 不同用户 | 第二个微信账号从自己的第一张开始，不看到他人进度 |
| 缺席一天 | 第一天领一张，第二天不打开，第三天打开后总共两张；改手机时间不会改变云端日期 |
| 手势 | 一张时左滑提示「明日再来哦」；两张时左滑历史、右滑回较新卡片；点击翻面，活动正文中的操作条件可读 |
| 网络错误 | 断网／调用失败明确提示，不能显示虚假领取成功或回退成本地进度；联网重试不重复领 |
| 拒绝订阅 | 点设置提醒后拒绝微信授权，不保存新的提醒计划 |
| 允许一次提醒 | 接受后，只有云端确认才显示成功，数据库 nextSendAt 为次日北京时间 09:00 |
| 个人下一张 | 收到消息标题应为发送时下一张未领卡；不打开页面时 card_progress 条数不增加 |
| 停止提醒 | 停止获云端确认后不再安排后续发送；已在途消息不能撤回 |
| 长期模式 | 仅有真实长期资格时测试三种频率，不能用一次模板冒充 |

不要为了快速验收在生产库修改领取日期、清空回执或伪造授权。跨日场景应留出实际时间；自动化隔离测试不能代替平台送达验证。

**首次上线的消息跳转限制**：现有发送代码使用 `miniprogramState: 'formal'`，跳转 `pages/index/index`。体验版不是正式版；尚未有正式版本时，不能承诺消息能跳入体验版。完整正式消息点击链路需首版发布后用知情账号验证；若必须预发布验证体验版跳转，需要开发者在隔离测试环境明确调整发送目标并在正式部署前恢复，不能把它当作现有配置项。

3. 填写隐私保护指引：说明微信身份关联、云端领取日期与卡片 ID、提醒计划和发送状态、处理目的、保存期限、删除渠道及运营者联系方式。不要承诺全部数据仅本机保存。
4. 说明不采集儿童文字、照片、语音；核验框架实际行为，不能将本说明当作法律审查或遗漏真实采集。
5. 建立真实可执行的查询／删除申请处理流程；目前没有应用内一键删账号按钮，不能在隐私文档声称已经提供。删除前需考虑幂等回执与重复发送风险，由有权限人员按批准流程处理。
6. 检查生产预算告警、数据备份及运维权限，保存发布版本、配置和验收记录，不在记录中公开用户 OPENID 或密钥。

## 第十三步：正式构建、上传、审核与发布

先确认 `.env.local` 指向**生产环境**，生产环境已完成集合、函数、权限、模板和触发器配置。不要上线后让所有用户连到测试库。

在项目根目录运行：

```bash
npm test
npm run type-check
npm run build:h5
npm run build:mp-weixin
npm run wechat:project -- build
```

1. 重新导入或重新打开开发者工具项目，确认 `project.config.json` 指向 `dist/build/mp-weixin/`，不是旧的开发产物。
2. 用正式构建真机预览，确认领取和配置正常。修改卡库时必须同时部署云函数与前端，因为两端共享内容 ID；不随意删除已有 ID。
3. 点击开发者工具顶部「上传」，填写版本号和清晰备注。**此按钮上传的是小程序包，不会替你部署云函数或触发器。**
4. 登录 https://mp.weixin.qq.com/ ，进入「版本管理 → 开发版本」，找到本次版本。先设为体验版完成验收，再点「提交审核」。
5. 按平台要求填写页面、类目、功能说明和审核资料，真实说明产品面向家长、无儿童能力评分，不编造资质或已上线能力。
6. 等待审核；若驳回，按具体原因修正后重新上传及提交。审核通过不等于已发布。
7. 在「版本管理 → 审核版本」点击「发布」，按实际情况选择平台提供的发布方式，由负责人确认。
8. 用普通微信入口打开正式小程序，确认生产环境领取记录；用知情测试用户订阅，验证次日真实消息标题、送达及正式页面跳转。

**上线完成标准**：正式版本可访问、云端进度正常、已开放的提醒能力完成真实授权与送达验证、必要资质及隐私流程完备。仅构建成功、上传成功或审核通过都不是完整上线。

## 常见故障与处理顺序

| 现象                 | 检查与处理                                                        |
| ------------------ | ------------------------------------------------------------ |
| 找不到云函数目录           | 是否导入仓库根目录；是否运行项目配置生成命令；cloudfunctionRoot 是否为 cloudfunctions/ |
| 提示未配置云环境           | 根目录 .env.local 是否有真实环境 ID；是否重启编译并重新上传前端                      |
| 云函数不存在／调用失败        | 前端环境 ID、工具选中环境及云函数部署环境是否一致；函数名是否 reminders；检查函数日志            |
| Cannot find module | 云函数依赖是否独立安装、上传部署是否成功；不要只传 index.js                           |
| 集合不存在／索引错误         | 三个集合名称是否准确；联合索引是否按顺序建好并完成构建；不要把安全规则改为公开                      |
| 未授权调用／缺少身份         | 必须从真实小程序调用；普通云端测试按钮不一定携带微信用户身份；不要手填 OPENID 绕过                |
| PROGRESS\_INVALID  | 云端进度损坏或与卡库不一致；保留原记录，先备份再排查，不清空用户进度掩盖故障                       |
| 提醒模式不可用            | 该模式启用标记、真实模板类型、ID、JSON、thing 标题标记及长度是否正确                     |
| 保存后没立即收到提醒         | 首次是次日北京时间 09:00，不是立即发送；检查 nextSendAt、定时器日志和授权状态              |
| 定时器没有运行            | 是否单独上传触发器；检查 cron、启用状态、环境及费用；不能只检查本地 config.json             |
| 提供方拒绝发送            | 查 lastResult 与云日志；核对模板、字段、授权、云调用权限及正式页面；不要不断重复发送             |
| delivery\_unknown  | 结果不明，系统故意不盲重发；核对平台记录，不删除发送锁／回执强制重试                           |
| catalog\_exhausted | 这个用户已领取当前全部内容，正常停止新卡提醒，不是已成功发送的意思                            |
| H5 和微信进度不同         | 正常：H5 仅本机预览，不使用微信身份；旧本机历史不自动迁移                               |
|                    |                                                              |

## 上线后维护与回退

- 每天检查函数错误、到期计划积压、发送结果、数据库用量及账单。当前每轮最多扫描 500 条计划，不代表经过大规模生产压测。
- 出现错误推送风险时，先在对应环境暂停／删除 `reminder-dispatch` 触发器阻止新一轮派发；已在途消息不能撤回。不要删除用户进度或幂等回执。
- 需要临时禁用某种提醒时，更新对应 ENABLED 配置。禁用会影响已有计划的状态，不是保证原计划无损暂停再自动恢复；恢复后需核对计划并按实际情况重新授权。
- 前端版本回退在公众平台版本管理中按平台可用能力操作；云函数需单独部署已验证的兼容版本，两者不会一起自动回退。
- 不回退到旧的按发布日期派卡逻辑，不删除已有内容 ID。发布前保留兼容代码包、配置记录和数据库备份；恢复备份是有风险的数据操作，应另行审批。
- 云函数环境变量调整后核对其生效状态；前端环境变量变更必须重新构建、上传并按平台流程发布。
