# 验证规范

本页是可执行的验收方法，不代表任何命令或设备验证已经通过。记录实际执行的环境、命令、结果与未覆盖范围；失败时保留错误并修复，不以未执行的检查代替证据。

## 初始化验收

1. 使用 Node.js 22，在项目根目录执行 `npm ci`，记录安装结果。
2. 执行 `npm run type-check`、`npm run build:h5`、`npm run build:mp-weixin`，记录退出状态及报错。
3. 执行 `npm run dev:h5`，在终端给出的地址打开首页；确认产品名称为“通识卡”、中文正常显示，所示为项目导览而非已经上线课程。在 320、375、414、768px 宽度检查无横向溢出；依次点击五个主题，每次仅展开对应的三个篇章，再次点击可收起；刷新后恢复默认主题，不保存用户选择。
4. 执行 `npm run dev:mp-weixin`，在微信开发者工具导入 `dist/dev/mp-weixin`，确认能编译并打开相同的项目导览首页，检查主题展开、收起与切换。若无法使用工具或 AppID，明确记为未验证，不将 H5 结果当作小程序通过。
5. 检查 H5 键盘焦点、字号放大、按钮名称与颜色对比；微信端检查触控目标、读屏名称和安全区。使用有代表性的实际设备或模拟器，注明设备和未覆盖项。

上述开发命令是常驻进程，人工验证结束后正常停止。构建成功与 UI 可用性、真机和隐私合规不是同一件事。

## 变更验收

- 内容：按[卡片规范](../content/card-standard.md)检查字段、正文字符、科学来源、分支、等待时长和安全替代，并由相应人员签发；不以计数脚本替代审校。
- 产品和界面：对照[路线图](../product/roadmap.md)及[界面规范](../design/ui-guidelines.md)，逐项检查已实现的功能和跨端差异；未实现项标注为规划。
- 数据及外部集成：在设计和开发前执行[儿童安全](../security/child-safety.md)评审；实现后验证同意、撤回、删除及权限拒绝等真实路径，不使用真实儿童资料做样本。
- 工程：改动涉及的平台都执行相关构建和类型检查；新增自动化测试时写明命令与覆盖范围。目前仓库不以本页声称已有测试套件。
