# 工程架构

## 当前实现

项目使用 uni-app Vue 3 + TypeScript CLI，以微信小程序为主要目标、H5 为预览目标。当前是单首页项目导览：`src/pages.json` 注册一个首页；`src/main.ts` 创建应用，`src/App.vue` 加载全局样式；根目录 `tokens.css` 存放视觉变量；`src/domain/curriculum.ts` 保存用于导览的主题和年龄分类，不是审定课程库。首页可选择五主题并展开或收起对应的三个篇章，选择不持久化。具体启动与构建见[开发规范](development.md)。

目前没有业务 API、服务端、账户、数据持久化、全局 store、自动化测试套件、在线 AI 或支付。白皮书中的地图、卡片打卡和手账是规划，不能由导览页面推断它们已经接入。

## 边界与演进

- `src/pages/` 放页面及页面级编排；跨页面复用的展示组件可放 `src/components/`，课程领域类型、纯规则可放 `src/domain/`。目录按实际需求创建，不预设空壳。
- 内容、视图和持久化分离：先有经过审校的结构化内容合同，再决定内容载入与存储方式；无数据或服务方案时不要伪造 API 或持久化成功状态。
- 遵循 uni-app 的页面注册、生命周期和组件模型，使用 `view`、`text`、`button` 等跨端组件及 `uni` API；H5 的 DOM、浏览器 API 或微信专属 API 只能在有明确平台判断和替代行为时使用。
- 应用密钥不进入客户端。涉及儿童资料、服务端和第三方处理须先按[儿童安全](../security/child-safety.md)设计和评审；任何 AI 功能都是未来决策，不是当前架构能力。

页面与业务增长后再按真实边界拆分服务或状态管理，不为当前导览引入闲置抽象。功能定义见[产品概览](../product/overview.md)。
