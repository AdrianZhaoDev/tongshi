# 家长传播海报

## 先读与输入

项目路径相对仓库根目录解析。先读 `AGENTS.md`、`docs/product/overview.md`、`docs/design/ui-guidelines.md`、`docs/security/child-safety.md` 和 `docs/ai/workflow.md`；引用卡片时再读 `docs/content/card-standard.md`。正式产品名为“通识卡”，定位为面向家长的亲子通识对谈与打卡工具；产品介绍描述目标能力，不代表当前已上线。不得使用认证标志或声称 IB 认证。

接收：海报类型、渠道与尺寸、主题和适龄段、文案来源及审校状态、已授权图形／字体、是否需要真实小程序码。真实金句另需原话的可追溯私有记录和监护人针对用途、渠道的授权确认；不得要求将含儿童身份的原始记录提交到公开仓库。

## 执行步骤

1. **先分流**：运营提问日签使用编辑撰写的开放问题，明确为“今日餐桌一问”等运营内容，不能配虚构孩子署名或包装成真实发言。真实金句必须来自真实记录，保留原意；没有记录或授权时停止金句分支，可明确改为不署儿童名的运营提问，不偷偷补造。
2. **最小化隐私**：公开成品不得出现儿童姓名、正脸、学校、班级、精确位置或可组合识别身份的细节。模糊署名也不能掩盖正文中的身份信息；授权并非公开这些信息的豁免。排除可识别儿童影像，选用有授权的中性图形。
3. **核对事实与承诺**：问题和附带科普须可追溯，未审内容仅用于带“未审”标记的内部方案；不得用“提高智商”“不学就落后”或成长诊断煽动焦虑，不伪造使用人数和家长推荐。
4. **安排版式**：依次明确问题／金句主层级、少量主题与年龄信息、“通识卡”品牌、可选行动提示和码区。使用设计规范色彩，保证中文可读与充分留白；按渠道裁切风险标明四边安全区的实际尺寸，重要文字与码不贴边。
5. **管理资源**：逐项列明图片、字体、图标的来源、许可证、商业使用范围与署名要求。无授权资源不使用，不调用图像服务替用户生成素材；若任务另行要求生成图像，先遵循相关技能和授权边界。
6. **处理小程序码**：只用已提供且经人工确认指向正确环境与页面的真实小程序码，保持比例、清晰度和必要留白，不装饰覆盖。缺码时明确标记“缺少真实小程序码，尚不可作为带码成品发布”，或在无需引流的交付中完全移除码区和引流承诺；不得画假码、把普通二维码冒称小程序码或用无法扫码的图案补位。

## 结构化交付

输出：

- **用途卡**：日签／真实金句、渠道、像素尺寸、版本、内部草案／待人工发布审阅。
- **最终文案**：标题、正文、主题／适龄信息、行动提示；区分原话与编辑文字，不编造儿童署名。
- **版式说明**：各区块位置与层级、字体与字号、配色、四边安全区、码区大小和留白；未实测的扫码可读性不得称已验证。
- **资源及授权表**：资源、来源、权利依据、允许用途、是否缺失；私有授权只记安全的内部引用，不复制敏感内容。
- **交付状态**：可提供的文案／设计稿／实际成品、缺失资源、未核验项、人工验收步骤。只交设计稿时不得声称海报生成功能已实现。

## 质检与人工闸门

逐项检查真实金句凭据与授权、公开信息去标识、科普审校状态、字体图片授权、对比度、长文截断、平台压缩与裁切、安全区、小程序码真实有效。涉及成品图时需人工查看最终导出图；涉及码时需人工在目标设备实际扫码。

只有运营负责人确认文案与渠道、监护人确认真实金句使用授权、内容与隐私负责人关闭阻断项后，才能交有权限者发布。AI不得替签授权、自动批准或自动发到朋友圈；本技能存在不代表仓库当前具备海报业务实现。
