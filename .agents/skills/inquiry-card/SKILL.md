# 微探究卡创作

## 先读与输入

所有项目路径相对仓库根目录解析。先读 `AGENTS.md`、`docs/content/card-standard.md`、`docs/content/curriculum.md`、`docs/security/child-safety.md` 和 `docs/ai/workflow.md`。白皮书示例只是规划素材，不能作为已核实事实引用。

接收：已确认的单元、卡片编号或命名规则、年龄段、主世界／篇章／核心大概念、日常场景、学习目标、禁用材料及已提供来源。缺少目标年龄或关键安全条件时先列缺项，不猜测后交付可执行活动。

## 执行步骤

1. 只处理指定卡片，沿用课程标识与字段。将主概念落实为一次可观察、可比较、可描述的体验。
2. 查证关键事实：优先科学机构、博物馆、权威教材或原始研究；记录准确标题、机构、链接或书籍页码、查阅日期及对应论断。无法访问或核实的条目标“待核实”，不能声称已查证。
3. 撰写约三分钟亲子对话所需正文，按卡片规范的字数口径控制为 200–300 字。来源、审校记录与内部元数据单独列出，不靠删安全提示凑字数，也不以缩小字号保证单屏。
4. 从具体生活场景提出开放问题；给出破冰、追问和简短点拨。明确两条分支：“答不出”提供可观察的线索或二选一比较后再开放提问；“想象回答”先接纳表达，再邀请观察事实，不嘲笑也不把拟人比喻当科学机制。
5. 写出约 30 秒微验证的材料、动作、观察点和停止条件，短操作不得超过一分钟。将准备和等待时间另列；现象不明显时允许“这次没观察到”，不承诺必然结果或编造观察记录。
6. 独立列出家长通识补给，解释类比的边界。用低风险替代活动消除危险；不把未知食材试吃、热水蒸汽、冰块长时间贴肤、陌生动物接触或近排水口观察直接搬入卡片。

## 结构化交付

交付一张卡的完整草案，依次包含：

1. **元信息**：编号、版本、`status: 草稿`（未审）、适龄段、世界、篇章、主概念、所属单元、目标；状态值沿用卡片规范，不新增同义枚举。
2. **家长可见正文**：今日探究、触发场景、破冰与追问、答不出分支、想象分支、启发点拨、30秒微验证、家长通识小密码；标明字数与统计口径，未实际计数时不得给出虚构精确值。
3. **执行边界**：材料、准备／操作／等待时间、成人职责、风险、停止条件与安全替代。
4. **事实台账**：逐条论断、事实或比喻、来源定位、已核实／待核实；无来源的论断保持未审。
5. **审校交接**：自检问题、修订记录、待人工确认项，不填写虚构审校人或批准日期。

## 质检与人工闸门

检查 200–300 字、两条应对分支、日常可触发、开放而非二元问答、微验证时长真实、核心概念一致、科学类比不误导。不要沿用“舌苔红点就是味蕾”“植物染色瞬间可见”等未核实或错误表述；复核观察对象和机制。

输出始终保留“未审”标签，交 `content-review` 后由人工内容与安全负责人决定是否可用。缺失来源或安全结论不得靠润色变成已通过；不生成儿童真实回答、诊断或虚构试用反馈。
